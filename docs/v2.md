# V2: voice and personal memory

V2 extends V0/V1 without changing their account, BYOK, device, confirmation or action-result
boundaries. DeepSeek remains the only conversational runtime provider. Speech recognition and
synthesis run locally on the configured THRYV backend host, which may be a different machine
from the user's browser or paired Companion. No V3 browser/research tools are included.

## Voice setup

From `backend/`:

```bash
uv sync --locked --extra voice
uv run --extra voice python scripts/setup_voice.py
uv run --extra voice uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-access-log
```

The explicit setup downloads faster-whisper `base.en` for dictation/commands, checksum-pinned
openWakeWord feature models for the experimental THRYV detector, and Piper `en_US-lessac-medium`
for local synthesis. Model files live
in ignored `.models/`. Runtime inference never downloads them. Keep `--extra voice` or
`--inexact` in local uv commands so an exact dependency sync does not remove the optional
speech packages. Without models/dependencies, text and memory remain usable and speech shows
a clear unavailable message. `GET /api/voice/status` reports installed speech capabilities.

Host settings `STT_MODEL_PATH`, `WAKE_MODEL_PATH`, and `TTS_MODEL_PATH` select local model paths.
There is no user-configurable wake keyword. See the upstream [faster-whisper implementation](https://github.com/SYSTRAN/faster-whisper)
and [Piper Python API](https://github.com/OHF-Voice/piper1-gpl/blob/main/docs/API_PYTHON.md).
Piper and the voice/model data have separate upstream terms; retain and review the downloaded
`piper-MODEL_CARD`, [Piper license](https://github.com/OHF-Voice/piper1-gpl/blob/main/LICENSE.md),
and [Lessac dataset terms](https://www.cstr.ed.ac.uk/projects/blizzard/2013/lessac_blizzard2013/license.html)
when distributing speech-enabled artifacts. THRYV does not bundle the downloaded models.

## Talk and fixed THRYV wake listening

**Talk → speak → about 1.3 seconds of silence → transcription → existing conversation →
DeepSeek/tools → observed reply → Piper playback.** Finish & send and Stop voice remain
available. Short pauses below the silence threshold do not finish a command. Recording is
capped at 30 seconds. A local energy-based VAD requires sustained sound before detecting the
end of speech; no separate external VAD service is used.

Under **Settings → Voice**, **Wake word (Beta): On / Off** defaults to Off and persists
per authenticated account. Enabling it explicitly grants listening consent; the browser must
also grant microphone access. The microphone status remains visible. There is no rename field.
The single canonical keyword is **THRYV**, pronounced “thrive.” Recognition accepts common
short prefixes such as “hey,” “hi,” and “okay,” case-insensitively, and recognizer spellings
of that same pronunciation. Mentions embedded later in unrelated sentences do not activate it.

For **“Hey Thryv, open Chrome”**, the entire utterance is buffered through the end-of-speech
pause. Local recognition checks the invocation, strips it, and submits **“open Chrome”** once
to the existing orchestrator. Chrome still requires the existing approval. **“Thryv, what
system am I connected to?”** uses the same utterance for the SAFE system-info request.
A keyword-only invocation enters command listening, with a ten-second no-speech timeout.
The experimental wake stage uses a THRYV-specific acoustic classifier over openWakeWord's
local feature models. PocketSphinx locates the keyword boundary; faster-whisper transcribes
the buffered command after it. Transcription cannot authorize activation, and vocabulary
guidance remains disabled. Wake detection still follows the utterance's VAD silence boundary.

**Wake word is Beta:** the current acoustic model passes about 8/12 combined synthetic
positive/negative checks, with both missed invocations and occasional similar-word activation.
This is not an 8/12 positive-only recall measurement. Talk is the recommended reliable fallback.
Wake defaults Off; a false activation cannot bypass existing tool permissions or confirmations.
The Beta accuracy limitation is accepted for V2; no further model tuning is part of this run.
See [verification](verification.md) and the [model card](../backend/app/models/README.md).

Only the bounded speech segment is sent to local recognition on the THRYV host. Unrecognized
speech is discarded without a DeepSeek request, chat row, memory, or action. Silence does not
continually upload. Wake capture pauses during recognition, model/tool processing, and speech
playback. Wait for its visible listening state before the next utterance. Browser Web Locks
allow one THRYV voice owner per origin; other tabs cannot capture the same utterance concurrently.
Hiding the tab, disabling wake listening, signing out, or cancelling releases microphone/audio
resources. Stop voice pauses wake listening until Resume or another explicit enable; it does
not silently change the saved account preference. It does not undo an already authorized tool.

The same state machine handles both inputs. Capture callbacks, manual Finish, timeout and VAD
share a generation guard and consume the recording once. Pending queued/running action messages
are not automatically spoken. TTS waits for observed results and uses the exact existing reply,
with Markdown markers removed and a 600-character limit. Cancelled inference is killed and a
replacement gets a bounded two-second opportunity to acquire the worker after cleanup.

## Memory behavior

Say/type **“Remember that I prefer Python projects to use uv.”**, then ask **“What Python package
workflow do I prefer?”** in a new conversation or login session. The Memory panel supports
preferences, facts, project context and decisions, plus view/delete/clear and enable/disable.
“Remember this: …” is supported when the fact follows it; a bare “remember this” asks for the
fact explicitly rather than guessing from chat history. Saving an explicit memory is trusted
application code, not a model's claim. Ordinary chat messages are never auto-extracted.

SQLAlchemy/Alembic extend the existing database with owned memory and setting records. Each
account has at most 200 memories of 3–500 characters; case-insensitive exact duplicates reuse
the existing record. Simple lexical relevance, plural normalization and a small synonym map
select at most four matching memories within 1,600 characters. There are no embeddings or
vector database. Only this bounded relevant data is added to the account-chat system context.
No other user's records are eligible. Saved content is labelled data, not tool authority.

Credential labels, common key/token shapes, credential URLs, Unicode-obfuscated labels and
long mixed high-entropy strings are rejected before an explicit remember request is persisted
or sent to the provider. This catches obvious secrets, not every possible unlabelled secret;
never enter credentials into memory. The conservative filter can reject innocent text.

Memory is ordinary database text, not application-encrypted. Deletion removes active memory
records, not separate chat mentions, backups or storage journals. Disabling blocks subsequent
saves/retrieval while retaining records for viewing/deletion. A request already in progress may
finish with context retrieved before a setting changed. See [security](security.md).

## API additions

All endpoints require an account session. Writes require the existing exact Origin and
`X-THRYV-Request: 1` header. User IDs and custom wake keywords are not accepted in request bodies.

| Endpoint | Behavior |
| --- | --- |
| `GET /api/memories` | Current user's enabled setting and records |
| `POST /api/memories` | `{content, category}`; validated explicit save |
| `POST /api/memories/settings` | Strict boolean `{enabled}` |
| `DELETE /api/memories/{id}` | Delete owned record; others return 404 |
| `DELETE /api/memories` | Clear current user's records |
| `GET /api/voice/status` | Local model/dependency availability |
| `GET /api/voice/settings` | Owned wake setting and fixed keyword THRYV |
| `POST /api/voice/settings` | Strict boolean `{wake_enabled}` only |
| `POST /api/voice/transcribe` | Validated mono 16-bit 16 kHz WAV, at most 30 seconds |
| `POST /api/voice/wake` | Opt-in only; same WAV; returns `{detected, command}` without executing |
| `POST /api/voice/speak` | `{text}` up to 600 characters; no-store WAV response |

## Personality and practical limits

THRYV is warm and conversational, focused for technical work, supportive when the user is
frustrated, and lightly playful only when invited. Tasteful occasional banter is permitted;
sexual responses, forced romance and claimed human emotions are excluded. Important technical,
medical/emergency, security, error, confirmation and permission messages stay clear. Trusted
result/confirmation text is never rewritten by the model. Text and TTS share the same reply.

English CPU recognition and one English voice are configured. Accents, distant microphones,
noise and overlapping speakers affect recognition; this is not speaker verification. Background
audio clearly speaking an invocation can still activate it. Use a quiet environment and turn
listening off when unwanted; consequential tools continue to require approval. Energy VAD can
wait too long with sustained noise or miss very quiet speech. There is no background OS wake
service, closed-tab listening, custom wake word, streaming speech, interruption/barge-in during
recognition/playback, or browser-independent microphone coordination. Physical microphones,
speakers, accents and noisy-room performance require device-specific acceptance beyond synthetic
audio tests. Safari/iOS microphone behavior is not certified by Chromium mobile emulation.
