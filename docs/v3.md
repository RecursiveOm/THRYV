# V3 — Public browser and live research

V3 builds on pushed V2 commit `ec0e841124b0c054fa1571f996182e04b4974be5`.
The existing account conversation route, orchestrator, typed registry, owned Action records,
Companion confirmations and voice pipeline remain the foundations.

## Public browsing

`search_web(query, source_urls?)` searches Bing's public RSS endpoint and reads up to two
sources. Optional likely official URLs are hints, never evidence until fetched. Results
are ranked by topic overlap in titles, URLs and search descriptions, with generic storefronts
deprioritized. Discovered URLs are interleaved with unverified hints so guessed URLs cannot
consume the whole reading budget. Broad or unavailable search results can still require the
user to supply an official URL. `open_webpage(url)` reads that page directly.
`inspect_webpage()` returns captured title, URL, text and numbered links;
`follow_web_link(link_id)` reads an existing link; `back_webpage()` returns the previous
captured page. Each conversation keeps at most five pages. Inspect/back report snapshots,
with retrieval timestamps, rather than claiming a fresh fetch.

This is structured HTTP/HTML browsing using aiohttp and Python's HTML parser, not a full
JavaScript browser. It is lightweight, free of hosted browser dependencies, and suitable
for public server-rendered documentation. It has no login, form submission, upload,
arbitrary JavaScript, private cookies, personal browser profile, PDF or CAPTCHA bypass.
Script-heavy/inaccessible pages fail explicitly. No page subresources are fetched.

Every public request uses a cookie-free session, no environment proxy/auth inheritance,
GET only, manual redirects, public-address validation and a DNS resolver that pins its
validated addresses into the connector. Private/link-local/loopback destinations,
credentials in URLs, non-HTTP schemes and nonstandard ports are rejected. Responses are
bounded to 2 MB, readable excerpts to 12,000 characters per page, links to 150 per page,
redirects to three, HTML nesting to 128 levels, and each request to 12 seconds.
Compressed responses are declined;
the client requests identity encoding. Search query and URL secret-shape checks reject
obvious credentials, not every possible unlabelled secret.

## Research lifecycle and grounding

The initial model requests one typed tool. Trusted code creates a SAFE public Action
without a device ID and runs a bounded workflow: search, read sources, synthesize.
There are at most eight high-level steps (up to six source attempts), 75 seconds including queue time, two concurrent
workers and eight admitted tasks per server process. Repeated source URLs and redirect
loops are bounded. The conversation stays busy until completion/cancellation.
Progress, Cancel research and source details appear in the chat and Recent Actions.
Cancellation conditionally closes the owned action; stale completion cannot overwrite it.
Session expiry/logout and provider disconnection prevent subsequent research steps.
An in-flight network request can finish before the next check. Shutdown cancels workers;
after a crash, durable unfinished actions expire rather than replaying automatically.

Synthesis uses the same runtime provider and personality, with **no tool interface**.
All retrieved text, titles and URLs are labelled untrusted data. Pages cannot authorize
tools, supply executable arguments, access keys/cookies or disable permissions.
Research-derived assistant history is excluded from subsequent tool-planning prompts,
so malicious captured text cannot acquire tool authority on the next turn.
The synthesis must return a bounded answer and valid fetched source IDs. Trusted code
builds citations from actual metadata; model-supplied URLs or invalid IDs are rejected.
Retrieved excerpts/titles/URLs/times remain available even if synthesis fails. Source-ID
validation does not prove every claim: model factual/interpretation errors remain possible.

Research metadata and captured text are ordinary owned database records, not encrypted
personal memories. Action audit records survive chat deletion. No webpages are automatically
saved into V2 memory. Relevant explicit preferences use V2's bounded retrieval; software
research can match saved tool preferences. Talk and successful Beta wake activations submit
to the same endpoint. VAD is unchanged; queued/running research does not trigger interim TTS.
Final speech retains V2's 600-character limit.

Account-chat prompts receive trusted configured STT/TTS status, the owned memory toggle and
selected Companion availability. Empty memory retrieval is distinct from absent memory storage;
ordinary facts are not automatically saved. Bare “remember this” still asks for the exact fact.
Offline Companion affects only device tools. Prior research turns are excluded from planning
without substituting assistant status text. Explicit search/research requests that produce no
model tool call enter the existing search tool with the user's topic; internal placeholder
responses are rejected. Synthesis accurately credits THRYV's live public retrieval while
retaining its own tool-free boundary.

## Local website opening

`open_url(url)` is CONFIRM because it launches a window on the selected paired computer.
It uses existing owner/session/device/online checks, expiring approval, Action ID and
durable Companion replay ledger. Companion independently validates the URL, then supplies
only that URL to the fixed Chrome executable/flags with `shell=False` and a dedicated
profile. It does not read the browser. `url_opened` means a new matching window was observed;
it explicitly does not verify page loading or final redirects. The desktop browser can
resolve/redirect normally; it is not the server research fetcher's network sandbox.
Do not sign into sensitive accounts in the THRYV-created profile.

VS Code also uses a fixed private profile at
`~/.local/share/thryv-companion/vscode-profile` to prevent launch forwarding to an existing
native Wayland instance that Xlib cannot verify. This profile has separate editor settings.
Application success still requires observing a new mapped window. Expired pending approval
is now distinguished from an approved action that Companion did not collect in time; deadlines
and single-execution rules are unchanged.

## Operations

Run `uv sync --locked` and `uv run alembic upgrade head` before starting V3; add
`--extra voice` when retaining local speech. Revision `37d6a04b213a` adds owned captured
browser state and research action details, and permits null device IDs for public research.
Downgrade refuses to discard research audit rows: explicitly export/remove them before
rolling back. Existing device actions retain their foreign keys and ownership checks.
No cloud speech, paid browser services, extensions, V4 integrations or public deployment
were added. Ordinary tests mock public pages/provider/device effects. Opt-in acceptance:
`node scripts/live-v3.mjs` from frontend and
`uv run --inexact python -m scripts.research_injection_smoke` from backend.
